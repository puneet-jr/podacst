# Phase 6 essay workflow operations

Use the existing Compose startup and Mac Ollama/models. No new dependency/model download is required. Additive migration `0004_essays` preserves prior sessions, source versions and volumes. One API worker shares one generation lock between research and essays. Do not restart while a model/test job is active.

Essay intent is explicit: `POST /api/sessions/{sid}/essays` with `workflow:"ship30"`, `topic`, `audience`, `constraints`, `client_message_id`, optional exact `source_path`, up to three bounded `focus_questions`, `use_session_context` and `timeout_seconds`. This distinct route invokes EssayService and the reviewed application skill, not the extractive chat selector. Natural-language automatic intent classification and a dedicated essay UI are not claimed. FastAPI's `/docs` exposes the typed API.

The server saves the user request and at most two previous user messages from the owned session, capped at1000 characters. Assistant messages and previous drafts are never factual authority. Explicit topic/audience/constraints are preserved. Same client UUID/request replays a saved terminal outcome; changed input conflicts. A new request UUID is required to deliberately start another workflow after failure. Only one running chat/essay is permitted in that session.

Typed NDJSON progress includes started, retrieving, planning, drafting, validating, repairing and a terminal outcome. A fresh Pi1.5.0 process plans with only `search_transcripts({query:"current"})`, performing actual hybrid retrieval with local Nomic. Subsequent drafting/repair stages disable all tools and receive the saved section evidence as explicitly delimited untrusted context. Safe traces distinguish actual search/tool execution from pinned-snapshot writing; no fake tool event is added. The Phase5 strict textual-call adapter remains available for outline planning. The first per-stage-tool attempt failed because the model wrote prose instead of calling the tool; that attempt is preserved separately. No default shell/filesystem/web tools, arbitrary extension discovery, cloud keys or fallback.

The reviewed application skill and length policy are explicitly loaded from `agent/skills/ship30/`. This is an app writing skill applied through the Pi extension/system boundary; broad Pi skill discovery remains disabled. The guide supplies style only; transcript passages supply facts. Six cited outline sections precede section drafts. Targets total about1200 body words, leaving room for title/headings around1250. One repair is available across outline and final draft, not one unlimited repair per section. The server keeps original failed model outputs and replaced sections for review.

Bounds: target1250, accepted1125–1375 words including title/headings but excluding separate reference metadata; contractions/hyphenated words and decimals count as single tokens, source labels/list ordinals/Markdown markers do not. `config.json` is reviewed server configuration; changes require revalidation. Six sections, at most eight fresh Pi stage sessions and ten provider requests: two requests/one tool for an outline, one request/no tools for writing. The one repair can be spent on outline or a section. Context4096; output1100 tokens for outline/850 per section. Prompt-message cap11200 bytes. Each stage90s, whole request600s default/900 maximum. Actual input/output usage is recorded; byte caps do not provide a universal tokenizer guarantee.

Retrieval uses up to three exact-scope hybrid queries, four passages/2400 estimated tokens each,15s per query and explicit sponsor exclusion. Round-robin source selection retains at most six distinct passage IDs. Outline excerpts are capped at4200 text bytes with per-source allocation before second excerpts; a section sees at most two complete original passages/6500 serialized bytes. A conservative minimum of three passages can reject otherwise usable narrow evidence; it is not semantic sufficiency proof. Related results remain unverified until review.

Deterministic validation checks length, six populated sections, supplied/section-scoped citation labels, attributed paragraphs or explicit Application blocks, bullets, limited bold, repeated sentences, obvious unmatched numeric/direct-quote claims and no embedded HTML/external links. These screens cannot prove entailment, hook quality, progression or useful advice. Passing them yields `needs_review`, never automatic completion. Failures keep draft/outline/source snapshots and exact errors.

`GET /api/sessions/{sid}/essays/{rid}` reopens all draft/validation/outcome state. `GET /.../{rid}/sources` returns owned stored originals and safe links. Unknown/cross-session access is404. `POST /.../{rid}/review` stores reviewer, hook/progression/factual_support/applications_distinct/complete booleans and notes. All criteria and deterministic checks must pass before one atomic assistant-message/source publication to that same session. A review cannot override a failed rubric. This is explicit local-evaluator review, not production authentication or an independent expert certificate.

`POST /.../{rid}/cancel` and stream disconnect cancel/reap the owned Pi worker and close its capability bridge. Stages/drafts already saved remain recoverable. Startup marks abandoned running essays failed; partial automatic resume is not implemented. Source snapshots are retained. Failed/unreviewed essays are available through the API and are not presented as successful chat replies. Markdown/HTML artifact generation, rendering and publication remain Phase7 or later.

Raw stdout protocol and stderr diagnostics are separate under private `chat_traces:/app/evidence/private-chat/essays/<run>/<stage>/`. Parent0700 protects prompts/evidence. Do not publish that volume. Safe authored test outputs/source evidence are in `docs/agent-transcripts/phase-06/`; no complete coding-conversation export is implied.
